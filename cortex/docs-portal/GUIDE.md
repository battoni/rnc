# Docs Portal — Method & Scaffold

The full method behind the dual-audience documentation portal. The trigger and rules live
in the `docs-portal` skill (`.claude/skills/docs-portal/SKILL.md`); this is the depth it
points to. Reference builds: `docs.trainingbeta`, `docs.impressao`.

---

## 1. What we're building and why

A single VitePress site that serves **two readers from the same pages**:

- **The owner / end user** — usually non-technical (a client, a product owner). They need
  to understand *how to use the system* and *how it works conceptually*, in plain language.
- **The next developer** — needs the schema, endpoints, architecture, conventions, and the
  *reasoning* behind each decision, so they can take over.

The insight: these are **the same pages at two depths**, not two sites. A `User/Developer`
toggle in the nav flips a class on `<html>`; pure CSS shows/hides depth-specific blocks.
Content never leaves the DOM, so search and SEO see everything regardless of mode.

This is especially valuable as a **client handoff artifact** (see the memory on the client
delivery model): the owner reads the User view to run their system; whoever they hire reads
the Developer view to continue it.

**Three pillars:**

1. **The switcher** — `mode.ts` + `ModeToggle.vue` + the `::: user`/`::: dev` markdown
   containers (registered in `config.mts`) + `mode.css`. Anti-FOUC boot script in
   `config.mts` `head` applies the saved class before first paint.
2. **The extractors** — read-only static parsers over the sibling sub-projects. They write
   deterministic JSON; the Vue data components render it. `--check` makes staleness a CI
   failure. This keeps the developer reference *true* without hand maintenance.
3. **The gate** — Vercel Edge middleware that forwards the visitor's session cookie to
   `GET {API_URL}/auth/me` and serves only for a staff user. Fails closed. Logic is pure
   and unit-tested so it runs under `node --test` with no Edge runtime.

## 3. The switcher in detail

- **State:** `mode.ts` holds a module-level `ref<'user'|'dev'>`, persists to
  `localStorage['{{SLUG}}-doc-mode']`, and toggles `mode-user` / `mode-dev` on
  `document.documentElement`.
- **Anti-FOUC:** the inline script in `config.mts` `head` reads localStorage and sets the
  class synchronously before Vue mounts — no flash of the wrong audience.
- **Authoring:**
  - `::: dev` … `:::` → developer-only block (hidden in User mode).
  - `::: user` … `:::` → user-only aside (hidden in Developer mode).
  - Inside Vue components, use `<DevOnly>` / `<UserOnly>`.
  - Default-visible prose (outside any container) is shared by both — write it for the user.
- **Why pure CSS, not `v-if`:** content stays in the DOM → local search indexes dev text,
  SEO sees it, and toggling is instant with no re-render.

**Voice rule of thumb:** if a sentence needs a table name, an endpoint, a class name, or
"because we chose X over Y", it belongs in `::: dev`. Everything a non-technical owner needs
to *operate* the system stays in the default flow.

## 4. Content map

Adapt names to the project, but keep the shape. Sidebar order = reading order.

| Section | Audience lean | Purpose |
| --- | --- | --- |
| **Home** (`index.md`, `layout: home`) | both | Hero + "how to read this" (explain the toggle). |
| **★ For you** (client handoffs) | owner | `highlights` (what we built), `feedback` (their points addressed), `hiring` (how to vet the next dev). Omit for internal docs. |
| **Guide** (`guide/`) | user | Step-by-step, one screen at a time. `getting-started`, `navigation`, plus a page per major flow. Plain language. |
| **Concepts** (`concepts/`) | both | How the system *works*: `overview` (with a Mermaid hierarchy), domain model, roles & access, key decisions. `::: dev` carries the DB/impl mapping. |
| **Operations** (`operations/`) | mixed | `deployment`, `migration` — runbook-style. |
| **Developer reference** (`reference/`) | dev | `architecture`, `database-schema` (`<SchemaBook>`, `<EntityDiagram>` per module), `api-endpoints` (`<EndpointTable>`), `views-navigation` (`<ViewNavMap>`, `<ReachabilityMap>`), backend/frontend conventions, i18n, testing, AI-driven development. Sidebar group `collapsed: true`. |

Home page should always include a short **"How to read this documentation"** block telling
the reader to use the User/Developer switch and what each depth contains.

## 5. Extractors

Each `extract-*.mjs` exports a pure function; `extract.mjs` orchestrates, sorts
deterministically, and writes `.vitepress/data/*.json`. `--check` regenerates in memory and
exits non-zero if the committed JSON differs (wire into CI / pre-commit).

**These parse a specific stack** (Laravel `routes/api.php` + migrations; app.rnc
`modules/*/views/routes.ts` + `NavTemplate.vue`). For an api.rnc/celer-derived project they
work after you:

1. Fix the **sibling paths** at the top of each extractor (the `new URL('../../<dir>/...')`).
2. Edit **`scripts/lib/modules.mjs`**: the `MODULES` list (docs functional areas), the
   `TABLE_MODULE` ownership map, and the `PHP_MODULE_TO_DOCS` / `VUE_MODULE_TO_DOCS` maps.

For a different stack, keep the **contract** (deterministic JSON in the shapes the
components expect) and rewrite the parsing. The data-component JSON shapes:

- `endpoints.json`: `{ generatedFrom, modules[], endpoints: [{verb, path, controller, action, module, permission, auth, status}] }`
  `permission` is `null` or a string of **layers joined by ` + `**: a `permission:` middleware on
  an enclosing `Route::group` and the route's own both run, so the route needs every layer
  (`ideas.read + ideas.create` = group + route). Inside one layer a comma still means *any of*
  (`users.create,users.update`). A rewritten extractor keeps that notation, and the page that
  renders the table explains it (legend in `docs.rnc/reference/api-endpoints.md`).
- `schema.json`: `{ generatedFrom, modules[], tables: { <name>: {name, module, status, columns[], indexes[]} } }`
- `views.json`: `{ generatedFrom, views[], navItems[], permissionGroups[], reachability[] }`

Never hand-write these tables in Markdown — drop in the component and let it read the JSON.

## 6. The staff gate

VitePress ships static HTML/JS, so a client-side check leaves files publicly fetchable. The
**Vercel Edge middleware** runs before any document is served:

1. No session cookie → redirect to login (don't even call the API).
2. Forward the cookie to `GET {API_URL}/auth/me`.
3. Serve only on `200` **and** a staff user (`gateDecision`). Everything else → login.

The staff permission is the one decision here that is easy to get wrong: pick a key the member
role does NOT hold, and assert it — `middleware/auth-gate.test.mjs` builds the seeded member's
payload and expects `isStaffUser` to refuse it.

`auth-gate.mjs` is pure and env-driven (`SESSION_COOKIE_NAME`, `DOCS_STAFF_PERMISSION`,
`DOCS_STAFF_ROLE_SLUG`) so it unit-tests under `node --test` and adapts to any APP_NAME / role
scheme without code changes. `DOCS_STAFF_ROLE_NAME` is optional and has **no default**: a role
name is free text an administrator types, so a name counts as staff only when this variable is
set — a default would open the docs to whoever first names a role that way. The `matcher` in `middleware.ts`
skips static assets so you don't pay an auth round-trip per file.

Link to the portal from the app's **staff-only nav** (e.g. a `Docs` entry gated on the same
permission), passing the docs URL via env (e.g. `VITE_DOCS_URL`).

If the docs should be **public**, delete `middleware.ts`, `middleware/`, and the gate env;
nothing else depends on it.

## 7. Placeholders in `templates/`

Replace these when copying the scaffold into a new `docs.<project>/`:

| Placeholder | Meaning | Example |
| --- | --- | --- |
| `{{SLUG}}` | lowercase project slug; used for the localStorage key (the session cookie has its own placeholder — it follows the API's `APP_NAME`, not the project slug) | `trainingbeta` |
| `{{TITLE}}` | site / hero title | `TrainingBeta Programs` |
| `{{TAGLINE}}` | hero tagline | `How the new system works — for you and the next dev.` |
| `{{DESCRIPTION}}` | site + package description | `Documentation portal for …` |
| `{{API_HOST}}` | API base URL **including** `/api` | `https://api.trainingbeta.com/api` |
| `{{APP_LOGIN_URL}}` | app login page (gate bounce target) | `https://app.trainingbeta.com/login` |
| `{{API_DIR}}` | sibling API folder name (for extractor paths) | `api.trainingbeta` |
| `{{APP_DIR}}` | sibling SPA folder name (for extractor paths) | `app.trainingbeta` |
| `{{STAFF_PERMISSION}}` | permission that marks staff — a key **no ordinary member holds**; check the seeded member role before choosing (`users.read` looks right and is not: it was in rnc's member role, so every self-registered account read the internal docs — LP-DOCS-01) | `permissions.update` |
| `{{API_SESSION_COOKIE}}` | the session cookie the API emits — Laravel derives it as `Str::slug(APP_NAME)-session`, so read it off the API rather than guessing from the project name (LP-DOCS-02) | `api-trainingbeta-session` |
| `{{STAFF_ROLE_SLUG}}` | staff role slug | `staff` |
| `{{BRAND_HEX}}` | primary brand color in `brand.css` | `#2f6fb0` |
| `{{BRAND_FILL_TEXT_HEX}}` | label colour on a brand fill (the active User/Developer switch, the PDF button) — must clear 4.5:1 on `{{BRAND_HEX}}`: dark ink for a light brand, `#ffffff` for a dark one | `#ffffff` |

After substitution, `npm install`, then `npm run docs:dev`. Adapt `scripts/lib/modules.mjs`
and the extractor sibling paths before the first `npm run docs:extract`.

## 8. Verification checklist

- [ ] Toggle flips content on a page with both `::: user` and `::: dev`; no FOUC on reload.
- [ ] Local search finds text that lives inside a `::: dev` block (proves DOM retention).
- [ ] `npm run docs:extract` produces JSON; the data components render it; `:check` passes.
- [ ] **No root `.vercelignore` lists a project that deploys, or anything the extractors read.** Vercel reads `.vercelignore` from the repository root for EVERY project in the monorepo, whatever each project's Root Directory says — a line meant to trim another project's upload strips the one being deployed. The portal builds from the API's `routes/`, `database/migrations/` and `app/Modules/`, and the SPA's `src/`; ignore the rest of those trees piece by piece, opening each level with `dir/*` before the `!` that keeps a folder, because a negation cannot reach inside an ignored directory (new.impressao lost every docs deploy to `ENOENT … routes/api.php`).
- [ ] `cleanUrls` agrees between `.vitepress/config.mts` and `vercel.json` — `true` on both, with `trailingSlash: false` on Vercel. VitePress writes links without `.html`; a `vercel.json` that does not say the same leaves each page answering at two URLs (`/guide/x` and `/guide/x.html`), which is how chapaja found it. JSON cannot hold the comment, so the pair is written down here.
- [ ] Default (User) view reads cleanly with zero jargon end-to-end.
- [ ] Sidebar is identical on every page; developer group is `collapsed: true`.
- [ ] `npm test` passes (gate logic) if the gate is wired; `npm run lint` is clean.
