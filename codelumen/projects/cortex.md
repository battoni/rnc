# Cortex — AI Knowledge Layer

Cortex is the **knowledge layer** of rnc's AI infrastructure. It holds the history of decisions, reusable prompts, and documentation about the overall AI setup.

Rules themselves are **not** stored here — they live at the monorepo root (`.claude/rules/`, `.cursor/rules/`) and activate automatically by file path. Cortex is the "why and history" around them.

## What lives in Cortex

| File | Purpose |
| --- | --- |
| `CHANGELOG.md` | History of every AI infrastructure decision and change |
| `README.md` | Overview of the AI setup |
| `generate-component-rules.md` | Pointer to the component `RULES.md` prompt (the `battoni-generate-component-rules` command is the only copy) |
| `hooks/` | Hook scripts (rule injection, formatting) |
| `sync/` | Sync tooling for distributing rules to target projects |

## Design principles

- **Monorepo-always** — rnc is used as a whole; modules are never forked standalone.
- **Single source of truth** — each rule's body is written once, in `.claude/`; the `.cursor/rules` copy is generated by `make sync-mirror`, and `make sync-mirror-check` fails when the two differ.
- **Glob routing** — rules activate automatically by file path.
- **Planning gap** — `/battoni-start-session` loads the right rules before any files are open.
